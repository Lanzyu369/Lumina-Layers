# 第二轮：组装与导出缓冲的内存优化

2026-09-14；延续 `Min/fix/vector-material-parallelism`，尚未提交或发布。

## 本轮改动

- 规范片层网格的坐标镜像采用分块原地变换，继续使用原来的磁盘映射数组，
  不再因两次镜像各自生成完整顶点和三角面副本。
- 三角面绕序、显式质心及已缓存法线保持原行为。法线也按原公式分块变换，
  用磁盘缓冲保存；不能仅清除缓存重新计算，否则 GLB 光照数据可能改变。
- 单个可原地变换的规范网格，组装准入按颜色数组和固定工作缓冲估算，
  不再一律要求另有两份完整网格空间。其他类型或只读网格保留原路径和保护。
- 3MF 写入前的有限值、索引范围检查分块执行，避免整份布尔校验数组。
- 写入器的 float32 顶点、uint32 三角面缓冲，在内存紧张时按块写入磁盘映射。
  材质分块导出的索引重定位直接写入最终缓冲，不再先生成一份完整 int64 中间数组。

没有增加用户参数，也不降低精度或减少模型面数。成功的自动写盘不提示资源不足。

| Linux 2 GiB 容器相关回归 | 141 passed |

| 实际原生小图 GLB 预览 | 与替换回旧变换实现的基准一致 |
| 已缓存面／顶点法线 | float32 写出字节完全一致 |

512 万三角面专项对比：两边从相同的磁盘映射输入开始，只比较坐标变换与导出数组准备。
旧路径峰值 **478.42 MiB**、0.312 s；新写盘路径 **400.60 MiB**、0.400 s。
完整写出数组 SHA-256 相同。该数字是单次专项测量，不是整个程序或所有模型的内存降幅。
Windows 完整自动生成与上一轮 27.917 s 接近，不能据单次结果宣称显著整体提速。
Linux 完整写盘峰值 559.59 MiB，也没有显示整流程 RSS 一定下降；仍会受解析状态和分配器影响。

## 仍然存在的边界

本轮针对剩余的大数组副本，没有把 SVG 解析和几何布尔计算全面改为磁盘算法。
复杂图的主要剩余耗时包括解析／遮挡处理、材料求解和网格计算。
几何操作具有跨区域依赖，不能为了省内存直接任意切块而改变遮挡、孔洞或边界。
单个几何操作、接触修复、颜色数组和原生写入器内部仍有最低工作内存需求。
磁盘映射还会使用可回收的文件缓存，不是零内存。

复杂 `benchmark.svg` 的基准继续显式使用既有解析回退，以便与第一轮保持口径。
更准确的既有问题位置是：**原生解析产生的几何进入材质分组并集时**，
`_union_run_group_geometries` 内的 GEOS union 报 TopologyException，
并不是已证明解析器自身报错。本轮没有改变布尔算法或偷偷绕过此错误。
该问题单独记录在 `.scratch/vector-material-parallelism/issues/03-native-group-topology.md`。

原始结果、脚本位于 `.scratch/vector-material-parallelism/round2-*`。
M5 尚未实测，本轮代码和新增测试已纳入第二轮交接包。
