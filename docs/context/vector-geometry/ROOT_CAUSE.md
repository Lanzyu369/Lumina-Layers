# 原生 SVG 坐标转换导致生成失败

## 已确认的原因

用户素材能够完成预览，但生成时在色块合并处抛出 GEOS 拓扑异常。用包含
PR #603 的真实 Windows 原生扩展重新构建后，原图仍能复现同一异常和坐标。

同一份原生 visible 输出，以整数坐标检查时全部有效；适配层乘非二进制比例
`grid_to_source_unit` 后出现两处自交。旧实现仍给结果标记
`geometry_normalized=True`，后续生成直接把它交给浮点布尔运算。

这不是 MemoryError，也不是打印机配置或下载注册错误。异常发生在 3MF writer
之前。先前使用旧安装扩展得到的 635 个无效图形不属于同一基线；新版扩展的
对照结果是两处。包版本字符串同为 0.3.0，不能代替二进制身份。

## 修复

1. 原生整数采用二进制幂比例无损编码，原始 bbox、viewport、单位和物理比例
   保存在显式坐标契约中。源单位浮点投影不再作为后续拓扑的权威输入。
2. 在色层合并之前，全部颜色区域共同进入既有打印网格。复用原生 canonical
   边界规则处理取整、接触和塌缩，再以共享边界构造平面分区并保留着色归属。
3. 打印布尔运算明确使用该网格。三角化也在整数打印坐标中完成，随后才转为
   毫米坐标做写出精度检查；这同时修复了另一个六顶点三角化反例。
4. 缓存与跨进程载荷携带坐标契约；恢复几何时恢复精度模型。旧派生缓存失效，
   不反向缩放旧 WKB 来猜测整数拓扑，不删除原素材或已确认编辑。
5. 耗材求解、材料并行、独立底板、已有分层网格和写出器继续复用。

## 为什么不是在异常处补修复

对已经损坏的源坐标 Polygon 调用 `make_valid` 或 `set_precision`，不能证明
原来的接触关系、孔洞和材料分区被保留。对用户原图做过的简单修复对照，即使
不再抛异常，输出仍可能无效。本次改变的是几何进入计算域的顺序与契约。

原图在修复环境中已完成真实 preview → generate → 3MF 下载。用户安装包的后端
SHA、扩展 SHA 及材料文件字节身份仍未全部对应，不能把本地成功写成其旧安装包
已经更新或实际打印通过。

## PR #620 复核发现的 R1 归属缺陷

独立复核指出固定精度的 `point_on_surface` 可能把归属采样点吸附到 cell 边界。
随后 `within` 对投影区域和源区域都会拒绝同一个边界点，导致正面积 cell 没有
owner。真实 `project_print_regions` 入口复现了该问题：一格宽的 `1 × 3` 矩形
从面积 `3` 变为空区域；由两块大方形和一格宽连桥组成的单 Polygon，投影面积
从 `200.001 mm²` 变为 `0`。这不是打印网格量化，因为输入顶点已经在目标格点上。

修复仅为归属查询创建一个 pointwise、无精度标记的只读几何视图，并从该视图
生成代表点。整数 cell 的顶点、投影网格、绘制顺序和源域补判变换均未改变；真实
孔洞仍可无 owner。定向测试覆盖一格宽区域、连桥形状的环方向/起点/负坐标平移、
双区域标签对照、孔洞与岛，以及实际原生 SVG 的按材料光学网格体积。

该反例证明的是一条可达输入路径曾会丢失有效区域，不证明用户原图此前受影响，
也不意味着早先记录的全部 361 个空标签都是此缺陷造成。原图 R1 后复跑及 cell
级旧/新归属差异见 [验证报告](TEST_REPORT.md)。

## PR #620 复核发现的 R2 规范化缺陷

R1 后复核进一步发现，已分配到整数 cell 的正面积覆盖在最后一次
`_native_grid_regions(..., 1.0)` 中仍会消失。该入口会再次调用 Clipper2 的 union
和路径清理；它既承担源坐标投影时消解舍入交叉的职责，又被用于已经拥有整数
标签的覆盖表达。两个阶段输入前提不同，不能因单位比例是 `1.0` 就重用同一清理。

真实生产入口反例为一个 `10 × 10` 格方形先绘制、后绘制的凹多边形覆盖除角上
`0.5` 格² 三角形以外的区域。旧输出标签面积为 `[0, 99.5]`，而 cell 归属面积是
`[0.5, 99.5]`；该三角形不是零面积，也未被后绘标签覆盖。复核报告中三个紧凑化
的实际捕获三角形（面积 `5.5`、`17.5` 和 `531.5` 格²）也在旧原生规范化入口
输出为空。

修复保留 `project_regions_to_grid` 用于真实坐标投影/舍入与 winding 清理；新增的
`canonicalize_grid_regions` 只接收整数格点边界，以共享 `NodeToGrid` 和
`BuildFilledFaces` 重新表达每个标签的 cell 覆盖，不再先用 `coverage_union_all`
制造自接触的 GEOS 中间面，也不重复运行 Clipper boolean union。按标签直接重建的
结果保留外环、孔、岛和点接触拆分；输入非整数时会明确拒绝，而不进行隐式量化。

这一区分仍保留初始投影的既有 winding/舍入处理，不推出“初次投影为空的几何都
正确消失”。最终空标签来源和实际原图 R2 前后面积详见[验证报告](TEST_REPORT.md)。

## PR #620 复审发现的 R3 自检控制流回归

`api_server.py` 的原生 SVG 安装包自检先检查 silhouette 是否为空；R2 添加的
坐标域能力检查被缩进到 `raise empty_silhouette` 之后。因此 silhouette 有效时
整个分支跳过，silhouette 为空时先抛异常，canonicalizer/projector 能力、短边
正面积探针和打印域有效性检查都不会执行。旧控制流会让新自检在能力缺失或探针
失败时仍返回 `status=ok`。

修复只把坐标域检查移到 silhouette guard 同级，并保持其位于
`svg_coordinate_domain is not None` 分支内；投影几何的有效性检查仍在同一域分支
内执行。silhouette 为空时仍用原 reason code 结束，也不运行后续探针。隔离控制流
测试覆盖能力缺失、零面积规范化、无效投影、合法路径调用次数和 CLI JSON/退出码；
它不冒充原生几何验证。配套扩展上的真实公开 SVG 自检与独立 wheel 自检另行记录在
[验证报告](TEST_REPORT.md)。
