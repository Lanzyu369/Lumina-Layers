# SVG 打印几何与走线验证

原生 SVG 解析、三角化、3MF 写出和切片填充是不同的验证边界。解析库的
二维区域正确，不能单独证明最终打印走线完整。

## 统一投影到可写出的坐标

`resolve_vector_writer_grid_mm` 返回不小于原最小格距和四个 float32 ULP 的
最小二进制幂格距。常见打印尺寸使用 `2^-13 mm`（约 0.00012207 mm）。
整数坐标范围受四个 ULP 的约束，因此整数格点乘以该格距能被 float32
精确表示。

这次选择发生在现有的共享打印分区入口，各色块继续使用同一套边界。
旧的 0.0001 mm 十进制格距只能保证某些点仍可区分，不能保证三点经过
独立 float32 取整后仍不共线。二进制格距消除了这次二次取整，而不是在
三角化后分别移动各色块或删除问题三角形。

写出面积检查先转换成真实 float32 顶点，再用 float64 计算行列式。
直接用 float32 计算乘积和差值，会把部分实际非零面积误算为零。
现有整数零面积耳片处理继续保留。

这个保证适用于规范打印坐标及保持该坐标域的变换。任意旋转、模型覆面
布尔运算和切片器内部重新量化需要各自验证，不能从二进制 XY 格距推导
出这些步骤必然保真。

相关回归覆盖真实失败三角形的最小数值样例、不同尺寸下的 float32
往返、共享分区与分块、覆面坐标域，以及已有十进制坐标域的消费。

## 模型覆面的最终实体与导出

底座布尔运算仍使用原生 Manifold 实体，直到切槽完成。模型旋转和打印
朝向确定后，`prepare_surface_base_for_export` 将底座转换到写入器实际
使用的 float32 坐标。如果短边或细长面在这一步塌缩，使用 `Mesh64`
在这些已量化的坐标上完成一次实体拓扑收缩；随后验证面面积、闭合性、
绕序和体积。无法表示的实体明确失败，不单独删除三角形来掩盖问题。
彩色图案和材料槽保持独立，反向内壳继续表示空腔。

这一步不能前移到模型旋转之前，也不能直接改用 Manifold 的 `Mesh`
默认 float32 容差：原工单中后者仍留下了两个共线面。原工单最终底座的
退化面从 54 个降至 0，全部彩色图案也为 0；最终 3MF 经 Bambu Studio
2.8.2.61 实际切片成功，七种材料均产生模型挤出。

原生耗材的 `filament_ids` 由 FatCat 从每个选中预设的继承链解析，按最终
材料槽顺序写入。A2L 的原厂启动 G-code 会索引这个数组；仅有
`filament_settings_id` 名称不足以构成完整工程。Lumina 不在成品 ZIP 中
补字段，也不改写启动 G-code 来绕过缺失元数据。

上述覆面工单关闭了擦拭塔自动排布。完整切片验证显式开启现有的
`enable_wipe_tower_auto_placement`，让模型与擦拭塔共同放入原 A2L 打印板；
保留关闭选项的产品语义，用户仍可自行在切片器中摆放。

## 按位置、层和材料检查实际走线

`scripts/verify_native_svg_slicer_outputs.py` 原有的退出码、每种材料正挤出
和重复切片指纹检查继续保留。`--coverage-probes` 可以为已知应填实区域
添加局部检查：

```json
{
  "BambuStudio": [
    {
      "x_mm": 128.0,
      "y_mm": 128.0,
      "z_mm": 0.08,
      "max_distance_mm": 0.15,
      "tool_id": 1
    }
  ],
  "OrcaSlicer": [
    {
      "x_mm": 128.0,
      "y_mm": 128.0,
      "z_mm": 0.08,
      "max_distance_mm": 0.15,
      "tool_id": 1
    }
  ]
}
```

这是格式示例，坐标必须按被测模型实际放置和独立预期填写。XY/Z 是
G-code 的毫米坐标，`tool_id` 是可选的零起始材料编号。检查点应位于
已知实心区域内部；距离上限由线宽、填充策略和坐标取整误差决定，
不能用待测 G-code 反过来选出总能通过的位置。

```bash
python scripts/verify_native_svg_slicer_outputs.py \
  --bambu-3mf /path/to/bambu.3mf \
  --orca-3mf /path/to/orca.3mf \
  --coverage-probes /path/to/probes.json \
  --artifact-dir .scratch/svg-reality \
  --report .scratch/svg-reality/report.json
```

每个检查点记录最近的真实模型挤出距离。检查处理 G90/G91、G92、挤出
模式、换料、G0/G1 和相对 I/J 的 G2/G3 圆弧，包括完整圆。塔、裙边、
支撑、自定义动作和跨层斜移不能冒充该点所在平面的模型走线。R 形式
圆弧不受支持，遇到它会明确报错，不会用弦线代替。

即使切片器退出码为零且每种材料都有挤出，任何指定检查点未覆盖仍返回
`toolpath_missing_region_extrusion`。没有提供检查点的历史报告只证明原有
检查通过；少量点通过也不等于所有区域得到完整覆盖。

## Arachne 已知丢填充边界

2026-10-20 的真实工单回放在 Bambu Studio 2.8.2.61 发现：输入截面完整，
Arachne 的内侧轮廓拼接留下约 0.210 mm 开口，超过按中心线间距计算的
约 0.203 mm 拼接阈值。随后 `separateOutInnerContour` 仅接受闭合环，
整片内部填充区域被丢弃。逐层检查发现原工单八层中有七层缺走线。

源码定位：
[WallToolPaths.cpp](https://github.com/bambulab/BambuStudio/blob/v02.08.02.61/src/libslic3r/Arachne/WallToolPaths.cpp)。
与 `v02.08.04.61` 标签比较，该 Arachne 文件没有变更；这不是已经确认
发布修复的问题。

相同几何改用 classic 的诊断对照恢复了全部八层。使用 Bambu 源码的
独立诊断程序将拼接距离改为实际线宽，也恢复了丢失的内轮廓；这只是
上游修复候选的局部证据，尚未验证其他模型的过度拼接风险。

Lumina 本次保留原有 Arachne 设置。打印网格精度修复与这个切片器缺陷
分别验证，不能用改变顶点后偶然避开触发条件来宣称修好了 Arachne。
