# 切片软件 Logo 统一设计

## 结论

Lumina 将在两处切片软件选择界面加入官方应用 Logo：

1. 设置页的“切片软件”下拉选择器；
2. 模型生成后的“用切片软件打开”按钮及其切片软件列表。

采用用户确认的 **统一 Logo 底座** 方案：Logo 放在固定尺寸的中性圆角底座内，软件名称仍作为主要文字信息。该方案提升识别速度和品牌感，同时保留现有紧凑布局、键盘操作、设置持久化、切片软件检测与生成行为。

本设计于 2026-07-26 经用户确认。

## 背景

设置页目前通过通用 `Dropdown` 以纯文字列出切片软件。生成后的 `SlicerSelector` 已使用软件品牌色区分主按钮，并在展开列表中使用小色点，但没有显示应用 Logo。

当前支持的设置 ID 包括：

- `BambuStudio`
- `OrcaSlicer`
- `SnapmakerOrca`
- `ElegooSlicer`
- `AnycubicSlicerNext`
- `FlashStudio`
- `PrusaSlicer`
- `Cura`

本机检测结果使用对应的蛇形 ID，例如 `bambu_studio`、`orca_slicer` 和 `anycubic_slicer_next`。现有 `frontend/src/utils/settingsOptionIds.ts` 已负责两套 ID 和历史别名之间的转换，Logo 功能不得再维护一套独立的别名规则。

## 目标

1. 用户无需逐字阅读即可识别常用切片软件。
2. 设置页与生成后的打开入口使用同一套品牌信息和视觉规格。
3. 不明显增加设置页高度，不把八款软件展开成常驻卡片网格。
4. 在浅色、深色和品牌色按钮上保持 Logo 清晰且尺寸一致。
5. 未知软件或缺失品牌配置不得破坏选择、打开或下载流程。
6. Logo 资源随前端本地打包，运行时不依赖第三方网络。

## 非目标

- 不改变支持的切片软件列表。
- 不改变 `/api/system/slicers` 响应结构。
- 不改变切片软件检测、默认选择、打开应用或下载 3MF 的逻辑。
- 不改变 `settingsStore` 的持久化字段、后端同步或配方导入导出格式。
- 不重做设置页、打印机卡片或生成操作栏布局。
- 不增加 Logo 管理后台、用户自定义 Logo 或运行时远程更新。
- 不因为本次纯展示优化修改公告、分享卡 schema 或可复现参数。

## 已比较方案

### A. 直接显示原始 Logo

在名称左侧直接放置约 22px 的应用图标。

优点是改动小、最节省空间。缺点是不同应用图标的留白、底色和外轮廓差异较大，放在同一列表中容易显得忽大忽小；部分 Logo 在深色背景或品牌色按钮上对比度不足。

### B. 统一 Logo 底座（采用）

把原始 Logo 放进固定尺寸、主题感知的圆角底座。设置选择器、生成按钮和展开列表复用相同组件，仅根据背景切换底座样式。

该方案保持下拉交互和页面密度，又能统一视觉尺寸，并为深色模式、品牌色按钮和未知软件回退提供稳定容器。

### C. 常驻品牌卡片

把切片软件改成两列或多列 Logo 卡片。

该方案浏览速度最快、品牌感最强，但八款软件会明显拉高设置页并挤压打印机选择区域，不符合本次“保持紧凑”的目标。

## 视觉与交互

### 通用 Logo 底座

- 标准底座尺寸为 `28 × 28px`，圆角约 `8px`。
- Logo 可视区域约为 `20–22px`，使用 `object-fit: contain` 保持原始比例。
- 底座不可被长名称压缩；文字区域负责截断。
- 中性界面中的底座使用现有浅色/深色表面和边框 token，不引入裸写主题颜色。
- 品牌色按钮中的底座使用高对比度浅色或半透明表面，避免 Logo 与按钮底色融在一起。
- Logo 与紧邻的软件名称表达同一信息，因此图片本身对读屏隐藏，按钮和选项仍由文字提供可访问名称。
- 不对官方 Logo 改色、裁切或重新绘制。

### 设置页

设置页保留现有单个下拉框：

- 收起状态：Logo 底座、软件名称、展开箭头；
- 展开状态：每一项显示 Logo 底座和软件名称，选中项继续显示现有选中状态；
- 未选中或列表加载失败时，不伪造一个品牌 Logo；
- 下拉框和列表行保持现有视觉高度，必要时调整内部垂直 padding，而不是增加页面占用；
- 长名称仅截断文字，Logo 和展开箭头保持可见；
- 纯文字使用方不传前置内容时，通用 `Dropdown` 的现有外观和行为保持不变。

### 生成后的打开入口

`SlicerSelector` 保留现有分裂按钮和品牌色：

- 可打开切片软件时，主按钮在文案前显示当前软件 Logo 底座；
- 展开菜单把现有品牌色小圆点替换为同一 Logo 底座；
- 设置中首选的软件、当前检测到的软件、选中状态和排序规则保持不变；
- “下载 3MF/ZIP”继续显示下载图标，不使用切片软件 Logo；
- 没有检测到切片软件时，现有下载流程和文案保持不变；
- 启动、自动生成或下载进行中时，加载动画占用 Logo 底座的位置，避免同时显示 Logo 和转圈造成拥挤，也避免按钮内容左右跳动；
- 禁用、成功、警告和错误状态保持现有语义。

## 前端结构

### 品牌信息

新增一个共享的切片软件品牌信息模块，职责仅包括：

- 由规范化的软件 ID 查找本地 Logo 资源；
- 提供显示所需的品牌样式；
- 为未知 ID 返回通用切片软件图形；
- 复用 `settingsOptionIds.ts` 的规范化和设置 ID/检测 ID 转换，不复制历史别名表。

如果现有 `SLICER_BRAND_COLORS` 和 `getSlicerBrandStyle()` 从 `SlicerSelector.tsx` 移入共享模块，原导出路径应继续转发这些符号，避免破坏现有测试或外部导入。

### Logo 组件

新增聚焦展示的 `SlicerLogo` 组件。建议输入包括：

- `slicerId`：接受设置 ID、检测 ID 或历史别名；
- `variant`：中性表面或品牌按钮表面；
- 可选的测试标识或附加类名。

组件负责规范化 ID、选择资源、渲染底座和未知软件回退，不负责选择状态、点击行为或业务文案。

### 通用下拉组件

为 `DropdownOption` 增加可选的前置展示节点，例如 `leading?: ReactNode`：

- 选中项的前置节点显示在收起状态；
- 每个选项的前置节点显示在展开列表；
- 未提供时继续渲染现有纯文字结构；
- `role="combobox"`、`role="listbox"`、`role="option"`、`aria-selected` 和现有点击关闭行为不变。

设置页是该能力的首个采用点，符合共享能力必须同时有实际使用方的仓库规则。

### 两个采用点

- `SettingsPanel` 为每个后端切片软件选项传入 `SlicerLogo`。
- `SlicerSelector` 在主按钮与已检测切片软件列表中直接使用 `SlicerLogo`。

这两个采用点共享资源、ID 规范化和回退逻辑，不各自维护 Logo 映射。

## Logo 资源与来源

资源应存放在前端品牌资产目录并由构建系统打包，不使用远程 URL 或运行时下载。

素材要求：

1. 优先使用切片软件官方源码仓库、官方网站或官方安装包中的应用图标；
2. 优先使用 SVG；只有官方未提供合适 SVG 时才使用足够分辨率的 PNG；
3. 记录软件名称、来源 URL、获取日期、原始文件名和适用的许可或商标说明；
4. 保留原始比例和品牌颜色；
5. 若某个素材的再分发条件无法确认，不复制来源不明的图片，先使用通用回退并把该软件列为素材审查项。

视觉回退不影响对应软件的选择和启动能力。

## 错误与回退

- 未知 ID：显示通用切片软件图形和 API 提供的名称。
- 已知软件但未配置 Logo：使用相同通用回退，不隐藏该选项。
- 品牌信息解析失败：不得抛出到设置页或生成流程。
- 远程网络不可用：没有影响，因为产品运行时不请求远程 Logo。
- Logo 加载失败：保持固定底座尺寸并切换到通用图形，避免布局塌陷。
- 切片软件列表 API 失败：继续使用现有错误提示和重试按钮。

## 测试

### 单元与组件测试

1. 品牌信息解析：
   - 八个设置 ID 均解析到正确品牌；
   - 对应检测 ID 解析到同一品牌；
   - 历史别名继续通过现有规范化逻辑解析；
   - 未知和空 ID 返回通用回退。
2. `SlicerLogo`：
   - 中性和品牌按钮两种底座样式；
   - 保持固定尺寸；
   - 图片对读屏隐藏；
   - 资源错误后显示通用图形。
3. `Dropdown`：
   - 前置节点同时出现在收起项和展开项；
   - 不传前置节点时维持现有纯文字输出；
   - 键盘/鼠标选择、选中状态和关闭行为不回归。
4. `SettingsPanel`：
   - 已加载选项显示对应 Logo；
   - 切换软件仍更新原设置 ID；
   - 加载、错误、机型过滤和喷嘴联动行为不变。
5. `SlicerSelector`：
   - 主按钮显示当前活动软件 Logo；
   - 菜单项显示各自 Logo；
   - 加载动画替换 Logo 而不是与其并列；
   - 未知软件正常回退；
   - 下载项仍显示下载图标；
   - 现有首选软件、检测软件和选择同步测试继续通过。

### 验证命令

- 通过 `python scripts/run_vitest.py run` 执行相关前端测试；
- 在 `frontend/` 中执行 `pnpm build`；
- 在 `frontend/` 中执行 `pnpm lint`；
- 手动检查浅色/深色主题、窄宽度、长名称、八款软件列表和品牌色按钮；
- 验证浏览器网络面板中没有 Logo 的第三方运行时请求；
- 手动验证后清理 Vite、Vitest 和浏览器验证产生的本地进程。

## 验收标准

1. 设置页收起项和展开列表都能显示对应 Logo。
2. 生成后的主按钮及切片软件菜单使用同一套 Logo 和底座规格。
3. 八款已支持软件均有明确的品牌解析结果；无法确认素材时使用通用回退且功能正常。
4. 未知软件不会导致空白选项、异常或无法启动。
5. 两处界面不维护重复的 ID/Logo 映射。
6. 设置字段、API、持久化数据、配方导入导出和生成结果均无变化。
7. 普通 `Dropdown` 使用方没有视觉或交互回归。
8. 浅色、深色、加载、禁用、错误和窄屏状态通过验证。
9. 产品运行时无需联网即可显示全部已打包 Logo。

## 风险与控制

- **品牌素材不统一：** 固定底座和 `contain` 缩放统一视觉占比，不强行改造 Logo。
- **商标或再分发条件不清：** 记录官方来源并逐项审查；不使用来源不明的聚合 Logo 包。
- **ID 映射漂移：** 复用现有规范化模块，并让设置 ID 与检测 ID 进入同一品牌解析测试矩阵。
- **通用下拉回归：** 前置节点为完全可选能力，并保留现有无节点测试。
- **加载状态拥挤：** 加载动画替换 Logo 所在槽位，保持按钮宽度和对齐稳定。
- **后续新增切片软件遗漏：** 未知 ID 自动回退；新增软件的完成条件同时包含品牌映射和测试。
