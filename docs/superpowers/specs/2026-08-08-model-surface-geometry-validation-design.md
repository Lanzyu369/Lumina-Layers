# 模型覆面几何校验与可诊断生成设计

## 结论

`LUM-20260807-001` 暴露的是模型覆面流程的阶段契约不一致：上传与预览只要求
模型可读取、可选面，最终生成却要求模型能够承受 Manifold 布尔开槽并在选区
下方提供足够壁厚。模型直到最终生成才触发这些约束，而领域错误又被统一映射为
通用 500，导致用户看到“预览正常、生成报错”。

修复采用防御式但不破坏模型的策略：在上传阶段拒绝确定无法开槽的网格；对由
多个独立闭合实体组成的模型，在开槽前做确定性的 Manifold 并集规范化；最终
生成仍失败时，把稳定领域错误码映射为可本地化的 422。不会自动封洞、删除零件
或体素化重建，因为这些操作可能改变钥匙孔、镂空结构和尺寸。

## 已确认事实与限制

- 工单使用 `UwU Ghast.stl`，选中 92 个面，覆面区域约
  `19.985 × 19.980 mm`，铺满、五层、层高 `0.08 mm`。
- 同一会话的预览成功，最终 `/convert/generate` 在约 1.27 秒后返回 500。
- 工单中的三份材料档案可以正常解析，材料损坏不是根因。
- 当前代码已经计算 `is_watertight`、`is_winding_consistent` 和 `body_count`，
  但上传端不会据此阻止不适合布尔运算的模型。
- 最终装配会检查局部壁厚并调用 Manifold 差集；相关 `ModelSurfaceError` 继承
  `ValueError`，因此被生成路由的通用异常分支转换成 500。
- 原始 STL 和服务端异常栈没有进入工单附件，无法证明该样本具体属于不闭合、
  壁厚不足还是布尔失败。实现必须覆盖这些已知边界，而不能声称恢复了缺失样本。

## 方案比较

### 方案 A：安全规范化、提前校验和结构化错误（采用）

在核心层建立唯一的布尔就绪检查。非闭合或非实体网格在上传时返回 422；多个
闭合实体在实际开槽前先做并集；局部厚度和布尔错误使用稳定错误码跨进程传递。
前端按错误码显示中英文操作建议。

优点是既能修复可安全处理的多实体模型，又不会静默改变不可靠网格；自动化测试
可以覆盖每条错误路径。代价是无法安全修复的模型仍需用户先在建模或切片工具中
修复。

### 方案 B：只把 500 改成 422（不采用）

仅在路由层公开错误。改动最小，但不闭合模型仍能完成上传、选面和预览，用户要
等待最终生成才知道失败，阶段契约仍然不一致。

### 方案 C：布尔失败后不挖槽直接贴面（不采用）

可以让请求返回 3MF，但色层会凸出原表面并改变外部尺寸；切片方向、材料接触和
机械强度也与“覆面嵌入”语义不一致，因此不能作为自动降级。

## 核心几何契约

新增 `core/model_surface/validation.py`，提供两个职责清晰的入口：

1. `validate_model_surface_mesh_for_boolean(mesh)`：确认三角网格非空、闭合、
   绕序一致且具有正体积。失败时抛出带稳定前缀的 `ModelSurfaceError`。
2. `prepare_model_surface_mesh_for_boolean(mesh)`：先执行上述校验，再把多个独立
   闭合实体通过 Manifold 并集规范化为可开槽网格；保留原始 metadata。

稳定错误码放在异常字符串开头，以便 `ProcessPoolExecutor` 只依赖异常 `args`
也能完整传递：

- `model_surface_mesh_not_watertight`
- `model_surface_mesh_not_volume`
- `model_surface_thickness_unknown`
- `model_surface_insufficient_thickness`
- `model_surface_boolean_failed`

错误码后可附带仅供日志诊断的数值，例如实际图案深度和最小局部厚度。API 不把
这些内部细节直接拼进用户文案。

## API 与前端行为

上传端在注册临时文件前执行布尔就绪校验：

- 不闭合模型返回 422，提示先修复网格后重新上传。
- 绕序或体积无效返回 422，提示修复法线/实体方向。
- 多实体但每个实体均合法时继续上传；真正开槽时统一规范化。

生成端在通用 `ValueError` 捕获之前单独处理 `ModelSurfaceError`。已知错误码返回
结构化 `detail`：

```json
{
  "error": "model_surface_insufficient_thickness",
  "message": "The selected surface is too thin for the current colour stack."
}
```

未知领域错误继续使用通用 500，避免公开内部异常。前端 API 客户端把已知错误码
映射到 `translations.ts`，因此模型上传和最终生成都会显示一致的中英文建议；
不增加新的 Zustand 状态、请求参数、持久化设置或分享卡字段。

## 自动化验证

测试必须遵循红—绿循环并覆盖：

1. 上传开口 STL 时，当前 200/后续失败的行为变为立即返回带稳定错误码的 422。
2. 闭合单实体模型仍可上传和选择表面。
3. 多个闭合实体进入布尔开槽时会先规范化，并保持外部几何与 metadata。
4. 局部壁厚不足、无法确定厚度和 Manifold 差集失败分别映射为正确 422。
5. 普通生成异常仍保持 500，避免扩大公开错误面。
6. 前端在中文和英文环境下把结构化错误码转换为本地化文案。
7. 修正现有生成路由测试中的 `FakePool.submit_timed` 测试桩，使它继续验证真实
   生产调用契约；该修正只属于测试适配，不改变产品行为。

## 真人式验收

自动化通过后同时运行 Chrome 与 Electron 用户路径：

### 失败路径

- 上传本机真实的非闭合双实体 STL `1mesh.stl`。
- 确认上传阶段直接出现本地化修复建议，不再进入选面/预览后才返回 500。
- 检查 Network 响应为 422，浏览器与 Electron 控制台无未处理异常。

### 成功路径

- 使用真实闭合 STL（优先 Bambu Studio 自带 `Bambu_Cube.stl`）和真实 SVG。
- 选择平面，使用“铺满”、材料来源、五层、`0.08 mm`，走预览和最终生成。
- 下载 3MF 后重新解析：确认基板与彩色材料对象存在、外部尺寸有限且模型为有效
  体积；确认下载链接可读取。
- 检查 Network 无 500、控制台错误为 0，界面状态和错误提示与实际响应一致。

原始 `UwU Ghast.stl` 未包含在工单或邮箱中，因此真人验收不能冒充原文件复现。
PR 必须明确记录这一限制，并分别提供真实失败模型、真实成功模型和自动回归证据。

## 范围边界

- 不自动补洞、删除组件、体素重建或无开槽降级。
- 不修改工单附件系统；保存覆面 STL 应作为独立后续改进。
- 不修改分享卡、设置持久化、材料配方或普通转换算法。
- 不运行与模型覆面无关的全量测试；使用模型覆面、API 错误处理、前端客户端、
  构建和真实用户路径的直接门禁。
