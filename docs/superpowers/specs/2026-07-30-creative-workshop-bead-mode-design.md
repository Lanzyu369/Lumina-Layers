# 创意工坊与拼豆模式设计

## 结论

Lumina Studio 在主导航的“图像转矢量”和“设置”之间增加“创意工坊”标签。创意工坊
不是一项写死的转换功能，而是一个带版本化模块清单、受控宿主能力和本地项目存储的
模块容器。

第一版只内置一个官方模块：“拼豆模式”。它读取清晰的数字图纸或截图，把不同形式的
拼豆图纸恢复为可编辑的逻辑矩阵，再根据相邻豆子的关系生成可连续调节的压合效果。
最终结果是只包含原始颜色和透明区域的平面 PNG，并通过受控交接接口进入 Lumina
现有的图像叠色、预览和 3MF 生成流程。

拼豆模式不是现有像素模式的另一个入口。它必须表现中心孔收缩、相邻豆子横向挤压、
四豆交汇凹点逐渐闭合、同色豆融合和异色豆清晰分界。它不模拟纸张、塑料高光、
阴影、哑光表面或其他材质纹理，也不新建一套 3D 建模管线。

## 研究结论

对中文图纸工具、公开视频、公开图纸和实物熨烫特写的观察表明，“拼豆图纸”至少包含
三类完全不同的输入，不能统一用格子中心取色：

1. **带色号的网格图**：每格中心可能是色号文字，图中还可能有粗细网格线、坐标、
   图例、数量统计和跨格水印。格子是否有豆与格子是什么颜色必须分开判断。
2. **硬边像素图**：通常是原始像素图按整数倍无插值放大，外围可能带标题、纯色背景
   或多个图案。白豆与白色背景完全相同且没有网格或透明度时，信息已经丢失，只能让
   用户指定背景并手工修正。
3. **圆豆预览图**：数字俯视预览把每颗豆画成带中心孔的圆环。颜色应从圆环本体采样，
   不能从中心孔采样。倾斜拍摄、光照不均和透视变形的手机实拍不属于第一版。

实物熨烫结果也不是两种不同的豆子。常见“有孔”和“无孔”外观来自同一种管状拼豆在
不同压合程度下的结果。轻压时中心孔和豆间空隙明显；继续压合后豆子横向扩张，四豆
交汇处形成十字、星形或菱形微孔；紧压时中心孔和交汇孔隙完全闭合。同色邻豆可能
成为连续色块，但异色豆仍保留边界。

中国用户当前常见的小尺寸拼豆按 **2.6 mm 中心节距**作为第一版默认值。这里的
2.6 mm 表示逻辑格点的中心间距，而不是要求压合后的外轮廓始终保持正圆直径。

研究样本还显示：

- 图纸尺寸并不固定，公开样本包括约 23×17、37×37、40×44、52×52、
  58×63、78×78 和 104×104 等规格。
- 有些制作者会故意加入噪点或水印。系统不应自动“修复”或去除这些内容，只能把受
  影响的格子标为低置信度并交给用户判断。
- 有些图纸使用透明 H1 等支撑豆来连接脆弱区域。透明支撑豆应参与邻域挤压和边界
  尺寸计算，但不增加 Lumina 的打印颜色。
- 图纸可能包含镜像版本、一张图中的多个图案或外部文字。系统应保留输入方向并要求
  用户先选定一个图案，不能自动猜测镜像用途。

## 目标与非目标

### 目标

- 在主导航中提供稳定的“创意工坊”入口。
- 建立可供后续官方或第三方开发者复用的版本化模块契约。
- 让官方拼豆模块成为该公开契约的首个实际使用者，不使用私有捷径。
- 从清晰图纸或截图恢复空格、彩色豆和透明支撑豆组成的逻辑矩阵。
- 提供校准、低置信格复核和基础矩阵编辑能力。
- 用邻域感知算法生成可视化、连续可调的真实压合形态。
- 以一格 2.6 mm 的推荐物理尺寸交给现有 Lumina 转换流程。
- 在本地保存项目，并通过分享卡恢复可编辑的拼豆矩阵和压合设置。

### 非目标

- 第一版不建设在线模块市场、账号、上传、下载、评分、评论或审核系统。
- 第一版不从界面安装或执行任意远程代码，只加载随 Lumina 发布或明确列入白名单的
  模块。
- 不支持倾斜手机实拍、透视校正、光照补偿或真实豆板照片识别。
- 不支持六边形、异形、非正交或品牌专用造型豆板；第一版只支持正方形网格。
- 不做色号 OCR、品牌色号自动映射或耗材品牌推荐；恢复并保留图纸中的源 RGB。
- 不自动去水印、去故意噪点或猜测缺失的白豆。
- 不模拟纸张、布纹、磨砂、反光、阴影、塑料厚度或熨斗温度。
- 不生成独立的拼豆 3D 模型；输出继续走现有图像叠色和 3MF 路径。

## 发布范围与拆分

首版由两个边界清晰、但在同一功能分支中交付的部分组成：

1. **创意工坊宿主**：导航入口、模块注册表、模块清单、受控能力、错误隔离和本地项目
   存储。
2. **官方拼豆模块**：图纸识别、校准、矩阵编辑、压合渲染、尺寸计算和 Lumina
   交接。

两部分必须同时落地。单独提交没有采用者的通用模块基础设施不符合仓库的 lighthouse
adoption 规则；拼豆模块直接访问转换器内部状态也不符合第三方接口目标。

## 用户流程

1. 用户打开主导航中的“创意工坊”。
2. 工坊首页显示官方“拼豆模式”卡片；第一版不显示市场、排行或在线下载入口。
3. 用户打开拼豆模式并选择清晰图纸或截图。
4. 模块自动判断输入更像色号网格图、硬边像素图还是圆豆预览图，用户可以手动改选。
5. 用户先裁出一个图案并确认行数、列数、网格起点和方向。
6. 用户指定一个空格样本；若存在透明支撑豆，再指定一个透明支撑豆样本。
7. 模块识别逻辑矩阵，并把不确定格子集中标记出来。
8. 用户使用画笔、橡皮、吸管、填充、透明支撑豆、撤销和重做完成修正。
9. 用户在“原图”“识别矩阵”“压合预览”之间切换，拖动“压合程度”并在局部放大窗
   中观察中心孔、豆间接缝和四豆交汇点。
10. 用户点击“交给 Lumina”。若转换器已有作品，宿主先确认是否替换；否则直接载入
    生成的透明 PNG，应用推荐物理尺寸并切换到现有转换器。
11. 工坊项目继续保留。用户可以返回修改并再次交接，转换器不会反向修改工坊矩阵。

首次进入创意工坊时显示模块首页；同一会话再次进入时恢复用户上次打开的模块和项目。
模块内部始终提供“返回创意工坊”入口。

## 创意工坊宿主

### 主导航

新增稳定标签 ID `workshop`，顺序固定为：

```text
… → 图像转矢量 → 创意工坊 → 设置
```

标签标题、模块标题、按钮、状态和错误文本全部来自
`frontend/src/i18n/translations.ts`，同时提供中文和英文。界面使用现有设计令牌并覆盖
浅色、深色和紧凑窗口；不引入硬编码的明暗颜色。

### 模块清单

每个模块提供只读、可序列化的版本化清单。第一版清单 schema 固定为版本 1，至少
包含：

| 字段 | 含义 |
| --- | --- |
| `manifestSchemaVersion` | 模块清单格式版本，第一版为 `1` |
| `id` | 全局稳定 ID；官方拼豆模块使用 `lumina.bead-pattern` |
| `name` / `description` | 可本地化的模块名称与简介 |
| `author` | 开发者或组织展示名 |
| `version` | 模块语义化版本 |
| `icon` | 随模块发布的本地图标引用 |
| `minLuminaVersion` | 最低兼容 Lumina 版本 |
| `inputKinds` | 接受的输入类型 |
| `outputKinds` | 可交接的输出类型 |
| `capabilities` | 模块申请的宿主能力 |

注册表启动时拒绝重复 ID、不支持的清单版本、不兼容的 Lumina 版本、未知能力和不在
发布白名单内的模块，并在工坊首页给出可理解的停用原因。

第一版随应用发布的模块仍把名称和简介的中英文源文案放在
`frontend/src/i18n/translations.ts`，构建清单时解析为本地化元数据。未来签名包可以
携带受验证的语言包，但不能用任意 HTML 代替纯文本元数据。

### 受控宿主能力

第一版模块只能通过版本化宿主桥接使用以下能力：

- `file.pick-image`：选择并解码受支持的本地图像。
- `project.read-write`：读取和保存该模块自己的版本化项目。
- `handoff.image`：向转换器交接经过验证的图像和推荐尺寸。
- `ui.theme`：读取当前主题。
- `ui.locale`：读取当前语言和模块翻译。
- `status.progress`：报告标准化进度。
- `status.error`：报告可恢复或致命错误。

模块不能直接访问 Zustand store、转换器组件、任意文件系统、用户设置或网络。官方
拼豆模块也只能使用这些能力。React 组件装载属于当前宿主适配层，不写入可序列化的
外部模块契约；将来改用 iframe 或 worker 沙箱时，清单和服务语义保持不变。

未来在线工坊需要另行设计包签名、权限确认、沙箱、内容审核、版本回滚和网络策略。
第一版只预留兼容契约，不实现这些功能。

实施时同步提供开发者文档，写明清单 schema、生命周期、能力语义、错误格式、版本兼容
规则和最小模块示例。官方拼豆模块是完整示例；示例不能使用公开接口之外的状态或工具。

### 项目存储

宿主以 `moduleId + projectId + projectSchemaVersion` 为键，将项目和原始输入保存在
浏览器本地持久存储中。模块只能访问自己的命名空间。写入采用先序列化验证、再原子
替换的方式，失败时保留上一份有效项目。

第一版界面只需要“继续上次项目”和“新建项目”，不建设完整的云项目管理器。原图、
矩阵和设置不会自动上传到新的服务。

### 错误隔离

每个模块拥有独立错误边界。模块渲染、识别或项目迁移失败时，工坊显示错误、重试和
返回首页操作；主导航、转换器和其他模块继续工作。标准错误对象包含错误代码、是否
可重试和本地化消息键，不能向用户暴露原始堆栈。

## 拼豆项目数据模型

项目 schema 第一版为 `bead-project/v1`，包含：

- 项目 ID、模块 ID、模块版本、创建时间和更新时间。
- 本地原图资源引用和输入分类。
- 裁切区域、行数、列数、网格起点、方向、翻转状态和校准样本。
- 调色板，保存精确的 sRGB 三元组。
- 行优先的格子矩阵。
- 低置信格索引及置信原因。
- 单豆节距、压合程度和渲染 schema 版本。

每个格子只有三种逻辑状态：

```text
empty
color(paletteIndex, confidence)
transparent-support(confidence)
```

占用状态和颜色状态彼此独立。这样白色彩豆即使与白背景接近，也可以依据格内色号或
非背景结构判定为“有豆”；透明支撑豆也不必伪装成一种打印颜色。

项目内保留原始行列和外围空格。交接时生成一个临时的裁边视图：只移除四周全部为
`empty` 的行列，内部空格不变，透明支撑豆视为占用并保留整体格点尺寸。裁边不会
破坏可撤销的项目原始矩阵。

第一版支持 1–128 行、1–128 列，覆盖研究中观察到的 104×104 图纸并限制浏览器内存
上界。超出范围时要求用户分图处理，不静默缩小矩阵。

## 图纸导入与识别

### 输入与分类

第一版接受可正常解码的 PNG、JPEG 和 WebP。文件大小、解码像素上限和 MIME 校验复用
Lumina 统一图片上传约束，不能再维护一套冲突限制。

自动分类结果为：

- `numbered-grid`：色号网格图；
- `hard-pixel`：硬边像素图；
- `ring-preview`：圆豆预览图。

分类只决定初始识别器，界面必须允许用户覆盖。分类不确定时默认让用户选择，不能在
后台强行采用置信度略高的结果。

### 两步校准

第一步用于确定几何：

- 裁出一张图中的单个图案；
- 确认行数和列数；
- 调整网格起点和单格宽高；
- 保留输入方向，并允许手动旋转 90°、水平翻转或垂直翻转。

第二步用于确定语义：

- 默认指定一个格内空格样本；空格只存在于图案外时可以从裁切边缘背景取样；
- 图案确实填满全部格子时可以明确选择“没有空格”，此时所有格子先按占用处理；
- 存在透明支撑豆时，可再指定一个透明支撑豆样本；
- 用户可以预览样本应用后的占用掩膜和颜色结果。

倾斜透视和任意角度校正不在第一版。若轴向网格无法对齐，界面应说明当前仅支持清晰、
正视的数字图纸或截图。

### 色号网格图

识别器先通过水平和垂直投影寻找周期性网格线，再用用户确认的行列和起点完成校准。
取色时屏蔽网格线和高梯度文字，从格子四角及低梯度像素估计背景色，不能取格子中心的
色号文字。

是否有豆单独依据格内非背景结构、色号笔画和与空格样本的差异判断，不要求完整 OCR。
因此白豆白底但格内带色号时仍可识别为占用；品牌色号本身不映射为官方色库。

### 硬边像素图

识别器通过横纵颜色游程和边缘周期寻找整数放大倍数，再把每个整数块还原为一个逻辑
像素。裁切外的标题和说明不参与识别。

若白豆和白背景在像素层面完全一致，输入不包含网格、透明度或其他可区分信息，系统
必须说明这部分不可恢复，并依赖空格样本与矩阵编辑，不能声称自动识别成功。

### 圆豆预览图

该模式寻找规则正方形格点上的重复圆环，在每个格子内从圆环本体采样颜色，并忽略中心
孔和豆间背景。它只面向数字生成或清晰正视的俯视预览，不尝试校正真实照片中的透视、
阴影和反光。

### 低置信处理

以下情况将格子标为低置信度：

- 网格线、文字或水印覆盖了大部分可取色区域；
- 同一格内候选颜色方差过大；
- 占用判断与颜色判断冲突；
- 圆环中心或边界位置偏离校准格点；
- JPEG 压缩导致候选颜色与相邻色难以区分。

编辑器提供“上一个／下一个不确定格”以及按候选颜色批量确认能力。系统不自动删除
水印、不平滑故意噪点，也不根据邻居把低置信格擅自改成“看起来更合理”的图案。

## 矩阵编辑器

编辑器提供：

- 彩色豆画笔；
- 橡皮；
- 吸管；
- 连通区域填充；
- 透明支撑豆工具；
- 撤销与重做；
- 网格显示开关；
- 原图、识别矩阵和压合预览切换；
- 低置信格导航；
- 返回校准。

所有操作只修改逻辑矩阵。识别器、编辑器和渲染器通过明确的数据结构连接，不能让
Canvas 像素成为唯一真相。撤销历史记录矩阵差异，不复制整张高分辨率预览。

颜色默认使用识别出的源 sRGB。用户可以选择现有调色板颜色或输入精确颜色，但第一版
不提供品牌拼豆色号映射。

## 压合渲染

### 选择的算法

采用**邻域感知的程序化压合场**，不采用逐格固定贴图，也不采用完整软体物理模拟。

- 固定贴图无法让相邻豆子共同形成真实接缝，同色邻豆也会一直留下重复边框。
- 完整物理模拟需要材料、温度、压力和时间参数，计算成本高，结果不稳定，而且超出
  Lumina 只需要确定性平面色区的目标。
- 邻域程序化方法可以按上下左右和斜向邻豆共同计算边缘，实时预览，并保证颜色归属
  确定。

### 压合参数

界面只有一个连续观感的“压合程度”参数，schema 中保存为 0–100 的整数，默认值为
50，并提供三个可点击锚点：

| 数值 | 名称 | 几何结果 |
| --- | --- | --- |
| 0 | 轻压／有孔 | 中心孔和豆间间隙明显，外轮廓仍是受压后的圆钝形 |
| 50 | 标准 | 豆子相互挤压，中心孔缩小，四豆交汇处保留细小十字或菱形凹点 |
| 100 | 紧压／无孔 | 中心孔和四豆交汇孔隙完全闭合 |

0 表示本工具可调范围内的轻压效果，不表示完全未熨烫的独立圆管。

### 几何规则

渲染器在归一化正方形格点上计算每颗豆的覆盖场：

1. 中心孔半径随压合程度单调缩小，在 100 时为零。
2. 外轮廓随压合程度扩张，并根据四邻和斜邻的占用方向向接触面变形。
3. 没有邻豆的外侧保持圆钝、轻微波浪的拼豆外边缘。
4. 相邻覆盖场重叠时，由到豆子中心的加权距离确定颜色归属；完全相等时按固定行列顺序
   处理，保证结果可重复。
5. 同色豆先求并集。在 100 时，同色邻豆间不得留下格线、十字缝或人为描边。
6. 异色豆即使在 100 时也必须保留清晰的颜色所有权边界，不混色、不加暗线。
7. 透明支撑豆参与占用场和邻域挤压，但其自身最终写为透明，不增加调色板颜色。

输出 RGB 只能来自项目调色板，alpha 只能是完全透明或完全不透明。禁止抗锯齿混色、
渐变、阴影、高光和额外轮廓色。通过足够高的每格采样分辨率控制视觉阶梯，而不是生成
新的边缘颜色。

### 预览与导出

默认完整渲染使用每格 32×32 像素。裁边后的 `cols × rows` 矩阵生成
`cols × 32` 乘 `rows × 32` 的透明 PNG。压合计算在本地 worker 中进行，主线程只
负责编辑交互和显示。

拖动滑块时使用自适应低分辨率预览并立即取消过时任务；停止拖动后生成 32 像素／格
的完整结果。编辑区提供一个固定局部放大窗，显示当前关注位置的中心孔、两豆接缝和
四豆交汇点。用户不需要导出后才能看出压合差异。

相同项目矩阵、渲染 schema 版本和压合数值必须逐像素得到相同结果。

## 物理尺寸

默认单豆中心节距为 2.6 mm。交接使用裁边后的逻辑矩阵计算：

```text
recommendedWidthMm  = columns × 2.6
recommendedHeightMm = rows × 2.6
```

例如 32×24 格的推荐尺寸为 83.2×62.4 mm。压合只改变格内和邻格交汇处的表面轮廓，
不改变格点中心间距。

透明支撑豆计入行列尺寸；内部空格也保持其物理位置。若裁边后没有任何彩色豆，宿主
拒绝交接并提示没有可打印内容。用户进入转换器后仍可主动改变最终宽高，但初次交接
必须应用推荐尺寸，保证“一格等于一颗 2.6 mm 拼豆”。

## 交给 Lumina

拼豆模块向宿主提交 `WorkshopImageHandoff`，至少包含：

- 模块 ID、模块版本和项目 ID；
- 渲染 schema 版本；
- PNG `File`；
- 像素宽高；
- 推荐毫米宽高；
- 行数、列数和单豆节距；
- 要求按完整图片画布计算尺寸的 `preserveCanvasBounds` 标记。

宿主验证来源模块、能力、MIME、图像尺寸、非空彩色内容和数值范围后，使用与现有
图像转矢量交接相同的正常图片载入入口，并原子地应用推荐宽高，再切换到转换器。
模块不能直接调用转换器 store。

转换器必须把 PNG 完整画布作为毫米尺寸的坐标范围，不能因外围透明支撑豆最终输出为
alpha 而自动缩短宽高。透明区域仍不生成实体，只保留其在格点布局中的位置。若现有
位图载入路径会裁掉透明边缘，受控交接适配器必须显式抑制该裁切，不能添加几乎透明或
伪造颜色的锚点像素。

若转换器已有源图或未完成状态，宿主显示一次明确的替换确认；取消后拼豆项目和转换器
都不变化。交接失败时保留项目、矩阵和渲染结果，允许重试。

再次编辑拼豆项目不会自动覆盖转换器。只有用户再次点击“交给 Lumina”才会生成新的
交接。

## 本地保存与分享卡

### 本地项目

自动保存内容包括原图、分类、校准、矩阵、低置信格、节距和压合程度。切换标签、进入
转换器或刷新页面后，可以恢复上一份有效项目。保存失败只显示非阻塞提示，不清除内存
中的当前项目。

### 分享卡 schema

当前分享卡 schema 为 v2。本功能将 schema 升级到 v3，在
`LuminaRecipe.recipe` 下增加可选的 `workshop` 段，内容包括：

- 模块 ID 和模块版本；
- 项目 schema 与渲染 schema 版本；
- 行数、列数和方向；
- 调色板；
- 使用行程编码压缩的格子状态；
- 单豆节距和压合程度。

分享卡的主资源仍是已经交给转换器的渲染 PNG。原始图纸截图不嵌入分享卡，避免文件
膨胀和重复传播水印内容。因此从分享卡恢复的是可继续编辑的矩阵项目，不能返回原图
重新校准。

导入带 `workshop` 段的分享卡时，转换器按现有流程正常恢复，并提供“回到拼豆工坊
继续编辑”的操作。若模块缺失、版本不兼容或工坊数据损坏，转换器仍使用主 PNG 正常
导入，只把工坊恢复标记为降级并显示警告。

v1、v2 分享卡继续按原逻辑导入。v3 的导出、导入、迁移、完整性哈希和 PNG 元数据
往返必须一起更新并有回归测试。

## 错误处理

| 情况 | 用户可见行为 |
| --- | --- |
| 图像无法解码或类型不支持 | 停在上传页，说明支持格式，项目不被覆盖 |
| 一张图包含多个图案 | 要求先裁出一个图案 |
| 网格周期无法可靠确定 | 进入手动行列和起点校准，不生成伪精确结果 |
| 信息不可恢复，例如白豆白底 | 说明原因并突出需要人工补画的区域 |
| 存在水印、文字或 JPEG 噪声 | 标记低置信格，不自动去除或修补 |
| 矩阵超过 128×128 | 要求拆分图案，不静默缩小 |
| worker 任务失败 | 保留矩阵，允许重新渲染 |
| 本地保存失败 | 保留内存项目，显示非阻塞提示和重试 |
| 转换器已有作品 | 交接前确认替换 |
| 交接验证或载入失败 | 保留工坊与转换器原状态，显示可重试错误 |
| 模块崩溃或版本不兼容 | 错误隔离，允许返回工坊首页 |
| 分享卡工坊数据不可恢复 | 正常导入主 PNG，工坊部分降级并警告 |

## 性能与任务取消

- 分类、识别、低置信分析和压合渲染在本地 worker 中执行。
- 每次校准或滑块变化都带递增任务 ID；新任务开始后，旧结果不得覆盖新状态。
- 拖动时可以降低每格预览采样，但不能降低逻辑矩阵精度。
- 在当前桌面 Chrome 开发环境中，52×52 图案的拖动预览应在 100 ms 内开始更新；
  104×104、32 像素／格的完整渲染应在停止拖动后 3 秒内完成。
- 主线程单次计算任务不得持续占用超过 50 ms；超出时必须继续拆入 worker 或分片。
- 临时 Blob URL、worker 和预览缓存在项目关闭或组件卸载时释放，不能跨模块泄漏。

## 隐私、权限与复现信息

- 图纸、项目和预览默认只保存在本机，不新增远程上传。
- 模块只获得清单声明且宿主允许的能力；第一版不提供网络能力。
- 错误日志不得包含图纸像素、完整矩阵、调色板或本地文件路径。
- Bug 报告上下文可以记录模块 ID、模块版本、项目 schema、识别类型、行列、压合程度
  和错误代码，但不能在用户未明确附加文件时自动携带原图或矩阵。
- 用户可见行为需要加入中英文公告；实施前按
  `docs/announcement-maintenance.md` 更新公告。
- 修改 Bug 报告上下文前必须按 `docs/bug-report-reproducibility.md` 同步前后端 schema、
  测试和结构化日志约束。

## 验证

### 自动化测试

1. **导航与宿主**
   - `workshop` 标签位于 `vectorizer` 与 `settings` 之间。
   - 标签切换、响应式布局、持久化和属性测试包含新标签。
   - 重复 ID、未知能力、不兼容版本和未列入白名单的模块被拒绝。
   - 官方拼豆模块只能通过宿主桥接读写项目和交接图片。

2. **识别样本**
   - 自制色号网格图覆盖细线、粗线、色号、白豆白底、坐标和跨格水印。
   - 自制硬边像素图覆盖 1×、8×、16× 整数放大、纯色背景、透明背景和外围标题。
   - 自制圆豆预览覆盖中心孔、相邻近色和透明支撑豆。
   - 多图案、低分辨率、JPEG 噪声和不可恢复白豆进入正确的人工修正路径。
   - 倾斜实拍和非正方形网格返回明确的不支持结果，而不是错误矩阵。

3. **矩阵编辑**
   - 画笔、橡皮、吸管、填充、透明支撑豆、撤销和重做保持矩阵、预览和导出一致。
   - 占用与颜色分离；透明支撑豆不进入打印调色板。
   - 返回校准后重新识别可以撤销，失败不会覆盖上一份有效矩阵。

4. **压合渲染**
   - 使用 2×2、3×3、同色和异色专用夹具验证 0、50、100。
   - 0 保留中心孔和豆间间隙；50 保留自然交汇凹点；100 完全闭孔。
   - 100 时同色邻豆没有格线，异色边界仍清晰。
   - RGB 集合是输入调色板的子集，alpha 只包含 0 和 255。
   - 透明支撑豆影响邻域几何但不输出打印颜色。
   - 相同输入、schema 和压合值逐像素一致。
   - 随机矩阵属性测试覆盖越界、空矩阵、单豆、内部孔洞和最大 128×128。

5. **尺寸、保存和交接**
   - 外围纯空行列被裁掉，内部空格和外围透明支撑豆保留。
   - 32×24、2.6 mm 的推荐尺寸严格为 83.2×62.4 mm。
   - 外围透明支撑豆保持完整画布尺寸，但不产生实体或伪造锚点颜色。
   - 转换器为空时直接载入；已有作品时取消替换不改变任何状态。
   - 交接失败、刷新和切换标签后项目仍可恢复。
   - 临时资源和 worker 正确释放。

6. **分享卡**
   - v3 工坊段经过 JSON、PNG 元数据、哈希和导入适配器完整往返。
   - 调色板、RLE 矩阵、透明支撑豆、方向、节距和压合值完全恢复。
   - v1、v2 分享卡继续导入。
   - 未安装模块或损坏工坊数据时，主 PNG 和转换器参数仍能恢复。

### 真人流程

在本地前后端和 Chrome 中至少完成以下流程：

```text
打开创意工坊
→ 上传三类图纸各一张
→ 校准并检查低置信格
→ 使用全部编辑工具
→ 对比压合 0 / 50 / 100
→ 交给 Lumina 并确认 2.6 mm 尺寸
→ 完成现有叠色预览和生成
→ 返回工坊继续编辑并再次交接
→ 导出分享卡
→ 刷新页面后重新导入
→ 回到拼豆工坊继续编辑矩阵
```

同时检查中英文、浅色、深色、窄屏、已有转换器作品时的替换确认、离线本地保存和模块
错误隔离。测试结束后关闭 worker、开发服务器和临时资源。

## 完成标准

只有同时满足以下条件，首版才算完成：

- 用户看到新的“创意工坊”标签和官方拼豆模块。
- 三类清晰数字图纸都能进入可校准、可修正的逻辑矩阵流程。
- 输出能明显表现拼豆压合，而不是普通方格像素图。
- 0–100 的变化可实时观察，100 时同色融合且所有微孔闭合。
- 输出不产生源调色板之外的打印颜色。
- 推荐物理尺寸严格遵守一格 2.6 mm。
- 项目、Lumina 交接和分享卡往返均不会丢失已确认的矩阵与压合设置。
- 官方模块使用的宿主接口具备版本、能力验证、错误隔离和开发者文档。
- 第一版明确不包含在线市场、实拍照片识别、材质纹理和独立 3D 管线。
