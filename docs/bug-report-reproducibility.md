# Bug Report Reproducibility

Use this guide before changing `/api/feedback/bug-report`, feedback ticket assembly, attachment collection, cleanup, email attachment handling, `scripts/load_bug_repro.py`, or any converter generation parameter captured for reproduction.

## Ticket Storage

- Bug reports submitted via `/api/feedback/bug-report` land as a ticket directory at `feedback/<YYYY-MM>/<ticket_id>/`
- `ticket_id` matches `LUM-YYYYMMDD-NNN` using the Beijing date
- If the daily serial exceeds 999, fallback format is `LUM-YYYYMMDD-<8-char-hex>`

## Ticket Contents

- `ticket.json`: canonical payload (`schema_version=3`) with user description, workflow snapshot, action history, client logs, attachments manifest, email status, and `assembly_status`
- `index.md`: human-readable index generated by the assembler
- `summary.txt`: Chinese summary optimized for AI assistants
- Optional bulky files: `original.<ext>`, `final.<ext>`, `lut.<ext>`, `materials.zip`, `screenshot.<ext>`
- Bulky files are attached independently when available via `FileRegistry` + copy; missing attachments are explicitly marked in the manifest, never silently dropped
- Final artifacts must be copied only from server-side `FileRegistry` ownership or an exact `/api/files/<file_id>` reference; client-provided `disk_path` values are diagnostic context only and must not authorize copying files into a ticket

## Assembly Model

- `submit_bug_report` uses the hybrid assembly model
- The synchronous path copies small attachments (original image / final artifact / LUT) and returns `assembly_status: "in_progress"` under about 2 seconds
- `finalize_ticket_async` runs via `BackgroundTasks` to pack `materials.zip`, render `index.md` / `summary.txt`, and send the email

## Converter Parameter Changes

When adding or changing converter generation parameters, update bug-report reproducibility capture in the same PR:

- `AdvancedParams` types
- `buildAdvancedParams`
- `WorkflowSnapshot.advanced_params`
- `BugReportContextPayload.advanced_params`
- `api/routers/feedback.py` sanitizer/schema if shape or limits change
- `api/feedback_index.py` rendering when triage should surface the value
- Matching frontend/backend tests

Validate with a real local bug report and confirm `ticket.json`, `index.md`, and `summary.txt` contain the expected state without `File`/`Blob`/data URL payloads.

## Materials And Email Attachments

- `materials.zip` excludes `_solver_cache/` because developers can rebuild it locally
- Materials bundling has a 30 second wall-clock timeout controlled by `LUMINA_FEEDBACK_MATERIALS_BUNDLE_TIMEOUT_S`
- Email attachments over `LUMINA_FEEDBACK_MAX_EMAIL_ATTACHMENT_MB` (default 40) stay on disk
- When email attachments stay on disk, the email body lists them with absolute paths so the on-call engineer can `scp` them manually

## Cleanup

- `run_startup_cleanup` runs inside the FastAPI lifespan
- Tickets older than `LUMINA_FEEDBACK_TICKET_TTL_DAYS` (default 30) lose bulky attachments but keep small metadata
- Tickets stuck in `in_progress` past the 10-minute grace window are tagged `interrupted` and logged for follow-up
- Set `LUMINA_FEEDBACK_STARTUP_CLEANUP=false` to disable startup cleanup

## Local Reproduction

To rebuild a session locally:

```powershell
python scripts/load_bug_repro.py <ticket_id>
```

The script copies every available attachment to `repro_sessions/<ticket_id>/`, extracts `materials.zip`, and writes a `repro_manifest.md` with the action history. The frontend shows a yellow badge when opened at `http://localhost:5174/?repro_session=<ticket_id>`.

## Structured Logging

Structured logging events are whitelisted under `FEEDBACK_STRUCTURED_EVENTS` in `tests/test_logging_exception_governance_unit.py`:

- `feedback_bug_report_submitted`
- `feedback_ticket_assembled_init`
- `feedback_ticket_assembled_done`
- `feedback_attachment_collected`
- `feedback_materials_bundle_packed_done`

Relay / rate-limit events from the existing flow are also allowed. WARNING / ERROR events (`feedback_ticket_assembly_interrupted`, `feedback_materials_bundle_packed_failed`, etc.) are off the INFO whitelist by design.
