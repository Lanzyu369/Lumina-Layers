# Material Solver Cache + B&B — Progress Log

## Goal
Replace beam-search pruning (which loses global optima) with:
1. Exhaustive B&B solver (MITM-decomposed + transmittance cutoff) — guaranteed optimal
2. Disk-backed 64³ Lab-grid cache per (palette, N, t, substrate) — first-hit rebuild, then reuse

## Key Design Decisions (from user Q&A 2026-04-17)
- Cache build trigger: MANUAL ONLY (button). No auto-build on material select.
- Cache miss fallback: per-image B&B (always optimal, never silently degrades quality).
- Buffer layers: `buffer_layers=1` by default → α_cutoff tuned so one extra "invisible" bottom layer is free.
- Cache format: 64³ Lab grid, .npz + .meta.json sidecar, under `materials/_solver_cache/`.
- Cache key: sha256(sorted(material fingerprints) + N + t + substrate)[:16]
  Material fingerprint = sha256(dir_name + E[6dp] + k[6dp] + C0_white[6dp] + C0_black[6dp])

## Algorithm: solve_optimal_bnb (MITM + transmittance pruning)
1. Precompute per-material affine: a_i=exp(-k_i*t), b_i=E_i*(1-a_i)
2. Enumerate top suffixes (M^(N/2)): arrays of (α_top, β_top, recipe_top)
3. Enumerate bottom prefixes (M^(N-N/2)): apply to substrate → bot_colors
4. Partition top suffixes:
   - SATURATED (max(α_top) < α_cutoff): bottom is irrelevant → evaluate once with canonical bottom
   - ACTIVE: evaluate with all bottoms
5. For each target color: track best (recipe, pred_color, ΔE)

## Performance Targets
- 6 mat × 10 layers, K=16 targets: ≤ 3s
- 10 mat × 10 layers, K=16 targets: ≤ 30s (with α-cutoff typical saturation)
- Cache build (64³ grid = 262K targets), 10×10: ≤ 90s
- Must be ≤ current beam search ΔE on ALL test cases (regression check)

## LUT Catalog Contract Decision (2026-04-25)
Legacy BasicSettings will read the two-level selector data from `GET /lut/details/catalog`, because that response already groups items by manufacturer and carries each item's `color_mode`.
`/lut/catalog` remains the existing legacy/native source catalog for `lutList`, native brands, and upload refresh compatibility.
`converterStore.fetchLegacyCatalog()` owns the new BasicSettings catalog request and cache; it must not call `useLutDetailsStore.fetchCatalog()` because the LUT details tab is lazy-mounted and BasicSettings must work independently.
The store may reuse the shared `api/lut.ts` apiClient wrapper and the canonical `LutDetailsCatalogGroup` / `LutDetailsCatalogItem` types from `frontend/src/api/types.ts`.

## Calibration Board Backing UX (2026-04-26)
Goal: simplify the Generate Calibration Board panel — the backing color picker is replaced with a hard-coded White backing, and a new "Backing Thickness" slider is exposed alongside Block Size and Gap.

Decisions:
- API: drop `backing` from `CalibrationGenerateRequest`; add `backing_thickness: float` (default 1.6 mm, range 0.4–3.5 mm). Router always passes `backing_color="White"` to core.
- Core: every `generate_*_calibration_board` / `generate_*_batch_zip` accepts an optional `backing_thickness_mm` (defaults to `PrinterConfig.BACKING_MM`) and uses it for the spacer layer count and 8-color recipe metadata. Backward compatible: omitting the kwarg keeps current behavior.
- Slider step is `PrinterConfig.LAYER_HEIGHT = 0.08 mm` so each tick adds one print layer; this matches existing converter validation (`MAX_BACKING_THICKNESS_MM = 3.5`).
- Frontend: `BackingColor` enum stays for backward compatibility but is no longer surfaced in `CalibrationPanel`; store loses `backing` / `setBacking`, gains `backing_thickness` / `setBackingThickness` (clamped 0.4–3.5).
- Tests: update `tests/test_calibration_routing_properties.py`, `tests/test_calibration_integration_unit.py`, `tests/test_calibration_properties.py`, and the matching frontend property/unit tests so they no longer assert `backing` and now exercise the thickness slider plumbing.
